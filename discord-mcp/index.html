Discord MCP: Unique Divine PC & AI

Unique Divine PC & AI is my privately operated Discord tool. I use it to publish announcements, read messages and threads in public server channels, and configure scoped automation and tooling in servers where I have permission to do so.

The tool connects through a Discord bot account and makes operations available to my AI agent tools through Model Context Protocol, or MCP. I use it much like a command-line tool. One example is coordinating Nibiru validator upgrades by reviewing prior announcements and preparing release communications.

Access and operation

I am the sole operator of the MCP connection. Being a member of a server where the bot is installed does not grant access to its tools. Posting and administrative actions require my instruction or an automation I configure with a defined scope. The bot’s Discord permissions limit its access.

The integration sends requested message content and context to OpenAI Codex for analysis and drafting. The bot does not maintain a dedicated user database or message archive. Conversation history and diagnostics can still retain tool results, as described in the privacy policy.

Privileged-intent review

The following describes the historical-message feature and the access check performed on October 10, 2026. Discord’s intent-review guide asks for the concrete use case and why alternative interactions cannot provide the needed context. Data handling and deletion are covered in the privacy policy.

Why Message Content is needed

I use the integration to retrieve existing announcements and surrounding replies from authorized channels, identify the relevant release and operational instructions, and prepare the next announcement using that context.

For example, before a Nibiru chain upgrade, I ask it to review earlier validator communications. The integration needs the message text to distinguish a release announcement from its follow-up instructions and identify proposal links, upgrade heights, timing estimates, and container references. Author IDs and timestamps alone cannot supply that information.

The requested access supports historical communication review. Posting a new announcement by itself does not require Message Content. This workflow does not require Guild Presences or a full member list.

Alternatives considered

Slash commands can initiate a request, but do not provide the text of unrelated historical messages. A message context command can supply the selected message; it does not supply unselected surrounding messages or an entire historical thread. Messages mentioning the bot also do not cover earlier announcements that did not mention it.

I could manually copy individual messages into the assistant. That changes the workflow into manual message selection and omits the bounded retrieval of surrounding context. The MCP integration instead retrieves the requested context through Discord’s API with an explicit channel and message limit. It is not used to crawl all guild history or build a searchable archive of members’ messages.

These alternatives follow Discord’s privileged-intent guidance.

Example announcement workflow

  1. I ask the assistant to review previous upgrade announcements in Nibiru’s mainnet-validators channel and explain the established announcement format.
  2. The assistant requests a small set of messages around a known announcement through the MCP tool discord_read_messages.
  3. Once content access is available, the tool returns the requested message text and context for analysis and drafting. I check the resulting draft.
  4. Publishing requires a separate instruction from me, or an automation I have explicitly configured. A read request does not authorize publication.
